# Satori Infographic Reconstruction Engine

This project rebuilds faulty AI-generated infographics into deterministic SVG/PNG layouts using real text and vector geometry. The source is treated as semantic/layout evidence; the final graphic is rendered through React + Satori rather than retouching the original raster image.

## Visual system

- Global font: **Roboto Mono** only.
- Primary accent: **#ccff00** neon.
- Surfaces: dark grey / near-black.
- Final text is real SVG text geometry generated by Satori, not AI-painted lettering.
- Slice 1 renderers: `qa` and `dashboard`.
- Requested `process`, `comparison`, or `timeline` layouts currently fall back to `dashboard` with the fallback reason recorded in debug output.

## Install and verify

```powershell
npm.cmd install
npm.cmd test
npm.cmd run typecheck
```

## Render the bundled examples

```powershell
npm.cmd run render -- --input data.json --output legacy-qa --debug
npm.cmd run render -- --input tests/fixtures/canonical-dashboard.json --output dashboard-smoke --debug
```
## Rebuild an AI-generated infographic image

Image and report extraction use the OpenAI Responses API. Set `OPENAI_API_KEY`; `OPENAI_MODEL` is optional and defaults to `gpt-5.6-sol`.

```powershell
$env:OPENAI_API_KEY="..."
npm.cmd run generate -- --input .\my-faulty-infographic.png --output rebuilt --debug
```

The image is bounded to 2048×2048 with Sharp before semantic extraction. The model recovers visible text, metrics, reading order, hierarchy, section intent, and composition hints. It is explicitly instructed not to invent missing values.

## Extract or validate without rendering

```powershell
npm.cmd run extract -- --input .\report.md --output report-data
npm.cmd run validate -- --input data.json --layout auto --debug
```

`extract` writes canonical JSON only. `validate` prints layout selection, quality warnings, score, and deterministic render-profile decisions. Supplying `--output` to `validate` also writes a `.debug.json` report.

## JSON mode does not use OpenAI

Canonical JSON and the supported legacy `data.json` fixture are normalized locally. Rendering them does **not** require `OPENAI_API_KEY` and does not make an OpenAI request.

Generated files are written to `output/` by default:

- `<name>.json` — normalized canonical data
- `<name>.svg` — deterministic vector render
- `<name>.png` — high-resolution raster export
- `<name>.debug.json` — layout decision, quality report, and render profile when `--debug` is used
## Pipeline

```text
ingest -> extract/normalize -> select layout -> quality/reflow -> render -> export
```

Input support in slice 1:

- Images: `.png`, `.jpg`, `.jpeg`, `.webp`
- Reports: `.txt`, `.md`, `.markdown`
- JSON: canonical schema or the bundled legacy QA fixture

The canonical schema can represent metrics, checklists, bullet lists, process steps, timelines, comparisons, callouts, cycle diagrams, and lightweight tables. Slice 1 visually specializes QA/checklist and dashboard/report compositions; other represented families are retained for later dedicated renderers.

## Legacy prototype

The original root-level Satori prototype is retained under `legacy/` for reference only. It is excluded from active typechecking and is not used by the supported CLI. The supported entrypoint is `src/cli.ts` through the npm scripts in `package.json`.
